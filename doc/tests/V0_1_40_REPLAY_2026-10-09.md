## Lot 1 — Acceptation cohérente d'une référence

Deux régressions échouent avant correction : accepter l'absence de capture
conserve les anciennes lignes ; une capture corrompue écrase une référence
valide. Le chemin IPC ignorait aussi les erreurs de copie et réécrivait les
captures utilisées par les anciens rapports.

L'acceptation construit maintenant une génération distincte de référence, puis
publie atomiquement le fichier du jeu avec son identifiant. Les rapports
historiques conservent leurs anciennes captures. Une sélection partielle garde
les attentes et captures des entrées non sélectionnées ou non exécutées. Le
champ `captured` du rapport est autoritaire : false n'adopte aucune ligne, même
si un fichier résiduel existe. Un fichier attendu mais absent ou corrompu refuse
l'acceptation ; une erreur de publication supprime seulement la génération
préparée. Aucun succès partiel n'est renvoyé.

Le fichier partagé du jeu conserve uniquement les requêtes et attentes, plus
un UUID de référence facultatif ; aucune ligne n'y est ajoutée. Sur une machine
sans cette capture, la comparaison reste possible par attentes mais le diff de
lignes n'a pas de référence locale. Aucun repli silencieux sur d'anciennes lignes.
Les fichiers antérieurs sans les nouveaux champs restent lisibles. Les anciennes
captures manquantes ou déjà remplacées avant ce correctif ne sont pas réparées.

La rétention conserve la référence active, celles citées par les rapports gardés
et l'enregistrement original. Les générations acceptées devenues inutiles sont
supprimées. Une acceptation est refusée pendant un rejeu pour empêcher sa purge
concurrente. Jeu et captures sont résolus sous le même verrou de workspace ; le
recalcul des colonnes ignorées et les nouveaux rejeux utilisent cette référence.
Le contrôle Pro existant est conservé. Aucune requête moteur n'est exécutée par
l'acceptation ; lecture seule, Sandbox et confirmation production ne changent pas.

Preuves réellement exécutées :

- 82 tests unitaires Replay Pro passent, dont onze nouveaux (driver simulé et
  fichiers temporaires réels). Sélection partielle, métadonnées seules, skipped,
  capture manquante/corrompue après une première copie, échec de publication,
  réouverture, workspace étranger, ancien format et rétention sont couverts.
- 268 tests unitaires Core desktop passent, aucun ignoré.
- `pnpm typecheck` et Biome ciblé sur `src/lib/replay.ts` passent. Les ajouts
  TypeScript sont des champs de types facultatifs, sans changement du bundle.

```bash
LIBRARY_PATH=/home/raphael/.cache/qoredb-v0-1-40-target/debug/deps cargo test --manifest-path src-tauri/Cargo.toml --target-dir /home/raphael/.cache/qoredb-v0-1-40-target -j 4 -p qoredb --features pro --lib replay:: -- --test-threads=1
LIBRARY_PATH=/home/raphael/.cache/qoredb-v0-1-40-target/debug/deps cargo test --manifest-path src-tauri/Cargo.toml --target-dir /home/raphael/.cache/qoredb-v0-1-40-target -j 4 -p qoredb --lib
pnpm typecheck
pnpm exec biome check src/lib/replay.ts
```

Une coupure avant publication peut laisser une génération orpheline, jamais
sélectionnée implicitement et récupérable par la rétention ultérieure. Pas de
promesse de fsync. Pas de test de crash, disque plein réel, profil natif v0.1.39,
transport Tauri ou base réelle pour ce lot. La sauvegarde concurrente depuis un
éditeur externe au processus reste hors de cette qualification.

## Lot 2 — Sauvegarde de l'enregistrement et démarrages concurrents

Deux autres défauts sont reproduits : l'échec de sauvegarde consomme
l'enregistrement, et des démarrages concurrents se remplacent (six succès sur
huit appels dans la reproduction). Le recorder garde maintenant son état sous
verrou pendant la préparation et la publication. Il ne le retire qu'après
succès ; les captures restent disponibles après erreur, et le texte original
reste intact même avec la politique de redaction lors de la sauvegarde.

La baseline est écrite avant le jeu, qui porte désormais son UUID. La création
utilise un fichier terminé puis un lien atomique refusant une destination déjà
créée ; les mises à jour continuent d'utiliser un remplacement atomique. Le
helper est partagé dans qore-service. Un système de fichiers ne permettant pas
ce lien renvoie une erreur et laisse l'enregistrement disponible ; aucune
suppression préalable ou écrasement de repli. Windows/macOS non exécutés.

86 tests Replay Pro passent, dont quatre nouveaux sur ce lot : erreur injectée
avec retry, vraie erreur de chemin avec retry et redaction, démarrages concurrents
et créations concurrentes du même nom. Six tests des helpers de publication
qore-service passent, dont le refus d'écraser une destination déjà publiée.
La vraie erreur de chemin utilise un fichier à la place du répertoire attendu ;
ce n'est pas un test de disque plein. Le transport Tauri n'est pas exécuté.

## Lot 3 — Cycle des références sur PostgreSQL réel

Instance PostgreSQL 16.15 jetable et dédiée, image locale `postgres:16-alpine`,
port localhost 54321 et données en tmpfs. Aucun service existant n'est utilisé.
Les trois nouveaux tests déroulent le cycle entier : référence initiale,
modification d'un BIGINT exact, rejeu différent, acceptation, relecture du jeu et
des captures depuis le disque, puis rejeu classé identique. Variantes : capture
complète, metadata-only et budget de capture d'un octet. Les deux dernières
n'exposent aucune ancienne ligne comme nouvelle référence. Les rapports conservés
continuent de pointer vers leurs anciennes captures.

```bash
QOREDB_TEST_POSTGRES_REQUIRED=true LIBRARY_PATH=/home/raphael/.cache/qoredb-v0-1-40-target/debug/deps cargo test --manifest-path src-tauri/Cargo.toml --target-dir /home/raphael/.cache/qoredb-v0-1-40-target -j 4 -p qoredb --features pro --test replay_e2e -- --nocapture --test-threads=1
```

Douze tests PostgreSQL passent, aucun ignoré. Les neuf scénarios existants
requalifient aussi masquage avant capture, refus lecture seule/production,
isolation des sessions/workspaces, annulation et A/B. La commande REQUIRED
interdit de compter une base indisponible comme un succès. Le conteneur dédié
est arrêté et automatiquement supprimé après les tests.

Contrôles finaux : documentation, diff et rustfmt ciblé passent. Typecheck/Biome
ont été exécutés au lot 1 ; seuls des types frontend facultatifs ont changé.
Aucun test Chromium ni budget frontend réexécuté pendant cette continuation.
Pas de nouveau driver, de dépendance, de changement de licence ou de version.
Ce sont des tests Rust avec PostgreSQL réel et des fichiers locaux, pas une
recette du transport ou de la fenêtre Tauri. Les autres moteurs restent ouverts.
