La candidate contient un chunk dynamique `QueryTrendsPanel` (4 404 octets bruts)
et un chunk `LineChart` (292 814 octets bruts), absents de la fermeture initiale.
Le simple ajout d'un import dynamique avait d'abord augmenté l'initial de
673 octets bruts et 312 octets gzip : le contrôle a échoué, car la réexportation
statique retenait encore le panneau dans l'entrée. Sa suppression produit la
réduction ci-dessus. Le poids total baisse peu : le bénéfice porte surtout sur
le code chargé statiquement, sans suppression de fonctionnalité.

Les autres ressources comprennent les images publiques et le HTML ; leur hausse
vient du HTML (+76 octets). Les logos de bases restent un poste à examiner :
`singlestore.png` pèse 416 574 octets, `starrocks.png` 372 505 et `neon.png` 332 413.
Ils n'ont pas été optimisés dans ce lot.

## Commandes et preuves

Le build de référence a été exécuté avant toute modification frontend :

```bash
pnpm exec vite build --mode production --manifest --outDir .perf/dist --emptyOutDir
node --input-type=module -e 'import { makeReport } from "./scripts/measure-bundle.mjs"; import { writeFileSync } from "node:fs"; const report = makeReport(process.cwd(), ".perf/dist"); report.comparison = {status: "not-requested"}; writeFileSync(".perf/baseline-v0.1.40.json", JSON.stringify(report, null, 2) + "\n");'
pnpm perf:bundle --baseline .perf/baseline-v0.1.40.json --output .perf/after-v0.1.40.json
pnpm test:perf
pnpm docs:check
pnpm exec biome check package.json
pnpm exec biome check --write --stdin-file-path=scripts/measure-bundle.js < scripts/measure-bundle.mjs > /tmp/qoredb-measure-bundle-check.mjs
cmp scripts/measure-bundle.mjs /tmp/qoredb-measure-bundle-check.mjs
pnpm exec biome check --write --stdin-file-path=scripts/measure-bundle.test.js < scripts/measure-bundle.test.mjs > /tmp/qoredb-measure-bundle-test-check.mjs
cmp scripts/measure-bundle.test.mjs /tmp/qoredb-measure-bundle-test-check.mjs
pnpm typecheck
pnpm exec biome check src/components/Interceptor/AuditLogModal.tsx src/components/Interceptor/index.ts
```

Les JSON locaux ignorés `.perf/baseline-v0.1.40.json` et
`.perf/after-v0.1.40.json` listent respectivement 83 et 86 fichiers, leurs tailles,
leur appartenance à la fermeture initiale et les métadonnées de comparaison.
Le tableau ci-dessus conserve les agrégats de cette exécution dans le dépôt.
Pour recréer une référence avec l'outil terminé, utiliser `pnpm perf:bundle
--output .perf/baseline.json` sur les sources choisies avant leur modification ;
ne pas remplacer la référence par la candidate pour obtenir un contrôle vert.
Le [guide de tests](../development/TESTING.md) décrit les comparaisons suivantes.

Validation : 17 tests Node réussis, comparaison finale réussie, contrôle
documentaire réussi, typecheck réussi, Biome réussi sur les scripts,
`package.json` et les deux fichiers frontend modifiés.
Les chemins stdin `.js` permettent de vérifier
les `.mjs`, exclus par les motifs de fichiers de la configuration Biome actuelle.
La sortie corrigée en mémoire est comparée aux sources pour vérifier leur

## Limites et suite

- Démarrage, RAM/CPU, fermeture/réouverture et grille volumineuse : non exécutés.
  Aucun gain de latence ou mémoire n'est déduit de la réduction JavaScript.
- Distribution, taille installée, sidecars et runtime IA : non mesurés ; aucun
  résultat macOS/Windows ni comparaison native Core/Pro disponible.
- La fermeture statique ne représente pas tous les imports déclenchés au
  démarrage : la locale sélectionnée peut être importée avant le premier rendu.
  Une trace WebView et la recette interactive du panneau restent à effectuer.
- La référence est le HEAD identifié, pas la release publiée v0.1.39 ; les
  mesures historiques avec d'autres versions/protocoles ne sont pas comparables.
  L'inventaire fonctionnel et les scénarios natifs de phase 0 restent ouverts.
