Branche `feat/v0-1-40`, HEAD `79a3664`, avec les lots précédents non commités

## Lot 1 — Correction de fidélité XLSX/Parquet

Critères : relire les fichiers réellement produits ; conserver les grands
entiers et décimaux exacts ; refuser les conversions destructrices au lieu de
produire silencieusement NULL, false ou un entier tronqué.

La référence `cargo test -p qoredb --features pro --lib export::` passe avec
cinq tests. Quatre nouvelles régressions échouent avant correction : grands
entiers XLSX écrits comme nombres arrondis ; décimaux/entiers non signés Parquet
perdus ; conversions incompatibles acceptées ; `INTERVAL` et autres types
contenant « int » classés comme entiers.

- XLSX conserve les entiers dépassant 15 chiffres décimaux comme texte. Les
  petits entiers restent des cellules numériques. Les décimaux déjà fournis en
  texte restent exacts ; les textes ressemblant à une formule restent du texte.
- Parquet exporte les décimaux, entiers non signés et types complexes comme UTF-8,
  sans prétendre produire un type logique Decimal. Les noms de types numériques
  sont reconnus explicitement, pas par sous-chaîne. Int64 et Float64 restent
  utilisés lorsque la conversion est exacte. Une conversion incompatible échoue
  sans inclure la valeur de cellule dans le diagnostic.
- Le masquage existant conserve son schéma texte et ses NULL. Les valeurs déjà
  arrondies par un driver avant export ne peuvent pas être reconstituées ici.

```bash
LIBRARY_PATH=/home/raphael/.cache/qoredb-v0-1-40-target/debug/deps cargo test --manifest-path src-tauri/Cargo.toml --target-dir /home/raphael/.cache/qoredb-v0-1-40-target -j 4 -p qoredb --features pro --lib export:: -- --test-threads=1
rustfmt --edition 2024 --check src-tauri/src/export/writers/xlsx.rs src-tauri/src/export/writers/parquet_writer.rs
```

Dix tests réussissent après correction, dont cinq nouveaux. XLSX est relu via
son archive ZIP et les cellules/shared strings XML ; Parquet via le lecteur Arrow.
Ces preuves portent sur les writers et de vrais fichiers temporaires, pas sur
Excel/LibreOffice, la boîte de dialogue Tauri ou une base réelle. Les tests de
masquage caché/partiel/empreinte existants passent aussi.

Les writers restent BUSL-1.1, derrière le feature flag Pro existant. Le lot ne
modifie ni préflight, ni lecture seule, ni confirmation production, ni Sandbox.
Ces frontières ne sont pas requalifiées par des tests de sérialisation.

## Lot 2 — Correction de publication et de faux succès

Trois tests reproduisent avant correction l'écrasement d'un ancien fichier après
erreur du flux, le fichier partiel laissé après annulation, et un événement
`Done` cachant un échec ultérieur du driver.

Le pipeline écrit désormais dans un fichier voisin unique, privé (0600 sous
Unix), puis le renomme après réussite du driver et de la finalisation du writer.
L'échec ou l'annulation supprime le temporaire et préserve la destination. Le
helper de publication réside dans `qore-service`, sans dépendance Tauri.
La progression finale utilise la taille réelle du fichier, y compris Parquet
compressé. La limite zéro ne produit aucune ligne ; les lots de lignes respectent
aussi les limites et l'annulation. Les diagnostics de flux passent par le
nettoyage partagé des secrets.

Les tests de régression utilisent un driver simulé, le pipeline et les writers
réels, et des fichiers temporaires réels. Ils couvrent l'erreur des six formats
compilés en Pro, l'annulation, l'erreur tardive après Done, le remplacement
réussi, les limites 0/1/2/10 (lignes et batches), l'échec de publication et une
conversion Parquet refusée pendant la finalisation. Le contrôle Core vérifie
aussi le refus XLSX/Parquet sans endommager la destination.

Limites : l'annulation n'annule pas une mutation éventuellement déjà exécutée
par le moteur. Ce lot ne change pas le préflight de la commande. Un arrêt brutal
du processus peut laisser un temporaire privé ; aucune garantie de fsync ni
de récupération après coupure n'est ajoutée. Le remplacement Windows/macOS,
le disque réellement plein et le dialogue natif ne sont pas exécutés.

Contrôles du lot 2 : 20 tests `qoredb --features pro --lib export::`,
12 tests `qoredb --lib export::` et 5 tests `qore-service --lib paths::tests`
réussissent, aucun ignoré. Même préfixe Cargo/target/LIBRARY_PATH que ci-dessus.
`pnpm docs:check`, `git diff --check` et `rustfmt --check` des cinq fichiers Rust
modifiés passent. Aucun changement de dépendance ni de bundle frontend.

## Lot 3 — Qualification SQLite réelle et correction des résultats vides

Trois tests ouvrent des bases SQLite temporaires, exécutent de vraies requêtes
et relisent les fichiers du pipeline. Douze combinaisons (six formats, sans
puis avec masquage de la colonne email) conservent l'entier 9007199254740993
et un décimal stocké explicitement en TEXT. Les NULL sont contrôlés dans JSON
et Parquet. Le masquage est une configuration de session synthétique ; ce test
ne passe pas par le coffre ni par les commandes Tauri. XLSX est relu comme ZIP/XML
et Parquet avec Arrow ; les autres formats sont contrôlés comme texte, JSON
aussi reparsé. CSV/HTML/SQL ne sont pas réimportés dans une application tierce.

La qualification reproduit un nouveau faux succès : une requête SQLite vide
produisait un Parquet de zéro octet annoncé Completed. Le driver n'émettait
aucune colonne faute de première ligne. Le driver partagé décrit désormais les
colonnes après un flux vide réussi, sans rejouer la requête. Les flux non vides
conservent leur décodage existant. Parquet refuse aussi de finaliser sans schéma,
y compris pour les autres drivers non encore qualifiés.

Les exports vides Parquet/XLSX/CSV sont désormais relus avec leurs colonnes ;
une erreur SQL réelle préserve un fichier précédent. Un test Core du driver
vérifie la séquence Columns puis Done(0), les noms, types et nullabilité.

Commandes supplémentaires (même préfixe LIBRARY_PATH et cible Cargo) :

```bash
cargo test --manifest-path src-tauri/Cargo.toml --target-dir /home/raphael/.cache/qoredb-v0-1-40-target -j 4 -p qoredb --features pro --lib export:: -- --test-threads=1
cargo test --manifest-path src-tauri/Cargo.toml --target-dir /home/raphael/.cache/qoredb-v0-1-40-target -j 4 -p qore-drivers --lib drivers::sqlite::tests -- --test-threads=1
```

Résultats : 24 tests exports Pro, dont les trois tests avec SQLite réelle, et
7 tests SQLite du driver partagé passent, aucun ignoré. Avant le correctif des
flux vides : deux tests réels passaient, celui du résultat vide échouait à la
relecture Parquet. Ni SQLx NUMERIC/DECIMAL SQLite, ni dates, ni la matrice des
autres moteurs ne sont certifiés par la fixture de décimal TEXT.
